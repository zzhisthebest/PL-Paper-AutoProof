## 2. APP 分支：设计 LR

我对 LR 感到奇怪，就偏不用 LR，直接证明目标 SN 定理。然后在 APP 分支遇到了这个 proof state：

```text
Gamma : context
t1, t2 : tm
T1, T2 : ty
H : has_type Gamma t1 (T1 -> T2)
H0 : has_type Gamma t2 T1
IHhas_type1 : strongly_normalizing t1
IHhas_type2 : strongly_normalizing t2
(1 / 1)
strongly_normalizing (tm_app t1 t2)
```

这里不能仅凭两个归纳假设证明 goal。所以我明白了，LR 的目的就是让归纳假设足以推出 goal。

于是我自己设计了第一版 LR：

```coq
Inductive R : ty -> tm -> Prop :=
  | R_intro : forall (T : ty) (t : tm),
      strongly_normalizing t ->
      (forall (A B : ty) (t1 t2 : tm),
        R (Ty_Arrow A B) t1 ->
        R A t2 ->
        R B (tm_app t1 t2)) ->
      R T t.
```

报错提示违反了 strict positivity，所以改了意思相同的一版：

```coq
Fixpoint R (T : ty) (t : tm) : Prop :=
  match T with
  | Ty_Bool =>
      strongly_normalizing t
  | Ty_Arrow A B =>
      strongly_normalizing t /\
      (forall t1, R A t1 -> R B (tm_app t t1))
  end.
```

同时写了 fundamental theorem：

```coq
Theorem fundamental : forall Gamma t T,
  has_type Gamma t T ->
  R T t.
```

这就成功解决了 APP 分支的问题。我也理解了为什么 001 的解答里，LR 往往要有 `forall t1, R A t1 -> R B (tm_app t t1)` 这个看起来很奇怪的条件。

## 3. ABS 分支：加强 fundamental

接着证明 fundamental theorem，在 ABS 分支遇到了新的墙：

```text
L : list atom
Gamma : context
T1, T2 : ty
t1 : tm
H : forall x : atom, ~ In x L -> has_type (update Gamma x T1)
(open t1 (tm_fvar x)) T2
H0 : forall x : atom, ~ In x L -> R T2 (open t1 (tm_fvar x))
(1 / 1)
locally_closed (tm_abs T1 t1) /\
(forall t0 : tm, R T1 t0 -> R T2 (tm_app (tm_abs T1 t1) t0))
```

归纳假设 `H0` 里是 `open t1 (tm_fvar x)`，而 goal 里是 `tm_app (tm_abs T1 t1) t0`，不能直接推导。

然后 Codex 说，要把 fundamental 加强成：用满足对应类型 LR 的程序替换自由变量后，得到的程序仍满足 LR。这样才能把归纳假设里的自由变量换成实际参数。但我当时完全不明白为什么要这样改，只是照着干。

总之，我们得到了一版 fundamental theorem：

```coq
Theorem fundamental : forall Gamma t T,
  has_type Gamma t T ->
  forall replacement : atom -> tm,
    (forall x T1, Gamma x = Some T1 -> R T1 (replacement x)) ->
    R T (subst_env replacement t).
```

我想了很久，后面也一直在想，才逐渐明白了一些：必须让归纳假设能够涉及实际参数 `t0`，就要把 `tm_fvar x` 替换成 `t0`，这就是引入 `subst_env replacement t` 的目的。而这样对 `replacement` 也有要求：替换进去的程序得满足一定条件，最显然的就是对应类型的 R。

当然，为什么 fundamental 变成这种“鬼样子”后，竟然还能用于证明 SN，我还没有直觉上的理解，也没来得及仔细想。

## 4. 补上 local closure 条件

### 4.1 fundamental 中的条件

然后在证明中，需要交换 substitution 和 opening 的顺序：

```coq
subst_env replacement (open t1 t0)
= open (subst_env replacement t1) (subst_env replacement t0)
```

为了使用这个交换性质，要求替换项 locally closed，于是给 fundamental 增加“所有 `replacement x` 都 locally closed”的前提：

```coq
Theorem fundamental : forall Gamma t T,
  has_type Gamma t T ->
  forall replacement : atom -> tm,
    (forall x, locally_closed (replacement x)) ->
    (forall x T1,
      Gamma x = Some T1 -> R T1 (replacement x)) ->
    R T (subst_env replacement t).
```

### 4.2 LR 中的条件

在证明 ABS 分支时，又遇到了一个具体问题。为了让归纳假设处理实际参数 `t0`，我构造了新的替换表：把新鲜变量 `x` 替换成 `t0`，其他变量仍按原来的 `replacement` 替换。

```coq
let replacement1 :=
  fun y => if y =? x then t0 else replacement y
```

使用刚才加强过的归纳假设，需要证明新的替换表也满足：

```coq
forall y, locally_closed (replacement1 y)
```

当 `y` 不等于 `x` 时，替换项是 `replacement y`，已有前提保证它 locally closed。但当 `y` 等于 `x` 时，替换项变成了 `t0`，需要证明：

```coq
locally_closed t0
```

而关于 `t0`，我手里只有 `R T1 t0`。旧 LR 不保证 local closure，所以这里推不下去。也就是说，fundamental 要求替换项 locally closed，而实际参数 `t0` 要被放进新的替换表，因此也必须满足这个条件。

于是我给 LR 加上 `locally_closed`，让 `R T1 t0` 能直接保证 `locally_closed t0`：

```coq
Fixpoint R (T : ty) (t : tm) : Prop :=
  match T with
  | Ty_Bool =>
      strongly_normalizing t /\ locally_closed t
  | Ty_Arrow A B =>
      strongly_normalizing t /\ locally_closed t /\
      (forall t1, R A t1 -> R B (tm_app t t1))
  end.
```

这样，fundamental 里就不需要额外加 `locally_closed (replacement x)` 了，因为已经蕴含在 LR 里，于是 fundamental 改回了：

```coq
Theorem fundamental : forall Gamma t T,
  has_type Gamma t T ->
  forall replacement : atom -> tm,
    (forall x T1, Gamma x = Some T1 -> R T1 (replacement x)) ->
    R T (subst_env replacement t).
```

到此为止，LR 和 fundamental 已经正确定义，可以打通整个证明路线。后面就是比较 technical 的 fundamental 证明过程，我当时先暂停了。
