# Proof Viewer

从已有 Claude Code traces 生成离线 HTML，比较同题多次运行的最终证明与修改过程。不调用模型，不执行 trace 中的命令，不修改实验数据。

```bash
python scripts/proof_viewer/build.py
```

默认包含 001、004、034、055、073、100 六题，每题 20 次运行，输出到 `benchmarkResults/feature_inversion_analysis_20_repeats/proof-viewer.html`。顶部选择题目，运行下拉框只显示当前题目的 20 次运行。数据在 HTML 内按题目压缩，切换时本地解压；使用新版 Chrome、Edge、Firefox 或 Safari 打开，无需服务、网络或额外文件。

六题均提供七类功能分块，每块内分开展示定义和引理，并支持引理陈述中的绑定变量名归一化。过程回放始终使用原代码。

- 最终代码对照：默认单栏阅读，可开启双栏对照。上方选择功能分块，每栏的下拉框选择运行；支持展开 proof、返回原文件或查看文本 diff。题面原有声明独立标记，默认不出现在分块筛选中。
- 完整过程回放：保留当前 trace 的每条记录，包括模型思考原文、文字回复、工具操作、系统及结束事件。工具调用、进度、返回按 ID 合并，在最后一条记录的位置展示；标明起止行号及穿插事件。可按类型筛选，也可按原始行号跳转。
- 左侧先显示「本步摘要」，下面完整显示原始内容。摘要单独保存，并通过原始记录的 SHA-256 匹配；没有摘要的步骤明确标记尚未生成，不用截断原文冒充摘要。摘要描述当时的判断和操作，不代表已核实模型的猜测，也不增加错误分类。
- 每一步能展开完整原始 JSON（保留所有字段和原文）。原始行号以清除计数更新后的文件为准。导出时校验每一行恰好归入一个步骤；最终归档作为额外节点，不冒充原始记录。
- 右侧跟随实际操作或编译输出涉及的 `.v` 文件，包括临时文件，也可手动切换已出现的文件。有可确认的修改时展示红绿 diff／修改后。编译输出原样保留在左侧，不标记或跳转报错行。不同文件的版本不互相比较。
- 声明的「修改记录」：筛选该声明在 Task.v 中发生变化的版本，不把不同草稿拼接为同一文件。

## 记录边界

### 具体问题与耗时

`analyze_problems.py` 为每次运行生成独立分析，使用 DeepSeek Flash + Claude Code、20 并行。模型完整读取 trace 后给出具体问题、步骤区间、证据行号与处理结果；秒数由 Python 根据原始时间戳计算，不由模型估计。正常设计、编写和验证不自动算成错误。混合设计与纠错、无法细分的 thinking 留在工作阶段，不计入问题耗时。区间不重叠，问题与其余时间合计为整次运行耗时。

```bash
source scripts/deepseek_cc_env.sh
python scripts/proof_viewer/analyze_problems.py --parallel 20
python scripts/proof_viewer/build.py
```

分析保存于 `problem_analyses/<case>/rNN.json`，完整输入、输出及调用日志放在带时间戳的目录。已有结果匹配 trace 的 SHA-256 且通过校验时跳过。分析失败不伪造结果，运行汇总会标明已分析数量。

单次运行显示具体声明与耗时；每道题的总览才按大类别聚合。总览百分比以已分析运行总耗时为分母；“涉及运行数”按运行去重，不把同一次中的多个问题算成多次运行。展开类别可回到具体问题和原始步骤。类别是初步分析，不是已经验证的因果归因。

摘要生成独立于 HTML 构建，默认使用 `gpt-6.1-sol`、`high`。完整 trace 保存为 `full_trace.json`，同一个 agent 使用只读脚本 `read_trace.py` 按字符位置连续分页读取，先读完整次运行，再按顺序生成所有步骤的摘要。不把长 trace 塞进首条消息，不分批独立总结、不截断原文。文件读取绕开首条消息的字符限制，但不消除模型的 context window 限制。整次摘要齐全时跳过；`--force` 重新生成并保留旧版备份。日志及实际输入保留在对应的 `rNN_whole_trace_*` 目录。原文中的思考和代码仅是待总结的数据，不让模型继续证明。若调用失败或输出不完整，报错并保留旧摘要，不退回分批模式。

```bash
python scripts/proof_viewer/summarize.py --case 001 --repeat 12
python scripts/proof_viewer/build.py
```

处理全部 120 次运行（跳过已有完整摘要），最多同时处理 20 次；每次仍独立读取完整 trace，不拆成多个批次。全部结束后自动更新 HTML，失败项记录在 `summaries/batch_*.json` 中，重新运行可补做失败项：

```bash
python scripts/proof_viewer/summarize.py --all --parallel 20
```

Shell 修改从命令文本中静态还原，所有操作只作用于内存中的文件内容，不执行原始命令、不访问脚本指定的真实路径。支持字面 heredoc 创建／追加、printf 写入、cp／mv、cat 拼接、head／tail 截取（包括负数计数）、常见 sed 替换与行编辑，以及 Python 的字符串替换、切片、列表修改和文件读写。Python 使用受限 AST 解释器，不使用 exec／eval，也不执行 import。按命令顺序追踪文件和备份，后续完整 Read／Edit 快照用于核对并重新确认内容。

全量检查各次运行最后一步的文件列表：

```bash
python scripts/proof_viewer/audit_snapshots.py benchmarkResults/feature_inversion_analysis_20_repeats/proof-viewer.html --output /tmp/snapshot-audit.json
```

清单区分没有快照、已有快照但未确认、已确认，并另外标记运行中删除的文件。仅被引用的库文件也可能出现在清单中，因此不能把每个缺失项都当成漏解析。删除文件保留历史快照，不再仅因删除而标成未确认；匹配已有完整版本的局部读取也不会使快照失效。

这不是完整 Shell／Python 运行环境。动态路径、复杂控制流、未支持的脚本与正则操作等仍保留原命令和输出，并将相关旧版本标为未确认；不能声称任意 Shell 都已完整还原。两个完整快照之间的变化不一定来自一步操作，界面标为「中间修改未完整记录」。编译输出可能针对草稿；不自动认定证明成功。最终状态来自原 results.json。

未能还原的 Shell 操作之后，已有快照标为「完整版本尚未确认」，直到后续完整读取、记录或可还原的完整写入。没有该文件的快照时，不显示其他文件冒充。局部 Read 按原始起始行号展示片段。工作目录按各条命令中的字面 cd 顺序更新，并跨调用保留；输出明确记录目录被重置时，跟随重置。编译路径使用执行该条命令时的目录，不用最后一次 cd 的目录回溯解释之前的命令。不执行命令、不求值 shell 变量。

同一次 Shell 调用里，前面已经还原的写入不会因后面的未知操作而丢失：保留该版本供查看，并标为待确认。待确认的内容不用于继续推算复制、追加或替换的结果，避免传播过时的代码。

没有完整 Read 时，可从 Edit 返回的 originalFile 提取修改前的完整文件。本批六题分别核对了 20 次运行的初始文件，同题内容一致。

## 功能分块

`blocks.py` 保存 001 的分类。`functional.py` 为新增五题分别标注定义的作用，再根据引理陈述引用的对象、前提与结论分类，不根据引理名称的前缀分类。绑定变量不作为全局 LR 名称，当前运行没有定义的 LR 也不从其他运行引入。没有识别出的声明显示为「待确认」，不强行归类。这是阅读导航，不是 Rocq 的语义判定器。

| 分块 | 内容 |
|---|---|
| 通用基础设施 | 名字、列表、映射和环境的基本操作，以及安全标注的基本运算 |
| Syntax | 程序与类型语法、打开、替换、自由变量、局部封闭 |
| Operational semantics | value、归约、求值分解及相关辅助 tactic |
| Typing | 类型规则及其性质，包括 typing 推出局部封闭 |
| 语义解释与 LR | LR、语义环境、LR 的闭包和构造引理 |
| 核心证明 | fundamental theorem 及其分支，包括 subtyping 的语义正确性 |
| 目标性质与最终证明 | 目标性质的定义和辅助引理、从 LR 提取目标性质，以及最终定理 |

边界：单纯操作 substitution 的引理属于 Syntax；维护 LR 的环境属于 LR；`step_lc` 属于 Operational semantics；`typing_lc` 属于 Typing。单独提取 SN 的引理属于目标性质，联合证明多个 LR 性质的引理仍放在 LR。一个声明组只归一块，互递归定义保留为同一组，不拆开 proof。分类用于导航，不表示两次运行的定理语义等价。

Refinement 中 qualifier 的打开与替换属于 Syntax，谓词解释与成立性属于语义解释，well-formedness 与 entails 规则属于 Typing。Secure STLC 中 ground、transparent 与最终可观察结果相同的引理属于目标性质；将 subtype 推导转为 LR 包含关系的证明属于核心证明。

每个功能块内先展示「定义」，再展示「引理／定理」，各组内按名称排序；少量 Ltac 单列为「辅助 tactic」。红绿 diff 按同名声明逐条对齐，某侧缺少的声明单独标出，避免仅因排列顺序不同而整段错位。

默认将引理陈述中的绑定变量归一化为 x1、x2 等，保留自由变量及全局定义的名字；可取消「归一化陈述中的变量名」查看原文。不支持的语法保留原文，不猜测。定义和 proof 不改名，proof 可展开查看。这只是消除命名差异，不判断任意两个引理是否语义等价。「全部代码」和过程回放始终保留原始内容与顺序；归一化不修改任何证明文件。

运行名称旁显示当前分块的声明组数及模型新增非空代码行（去掉嵌套注释）。题面原有定义不计入新增行数；原有目标定理只计补全的 proof。import、notation、模块命令等仍可在「全部代码」中查看，不计入分块统计，因此分块行数不是整个文件的物理行数。原始代码行号不变。

空思考消息显示「思考文本为空」，不补写。原始时间戳照录，工具耗时不用于重新计算实验耗时。
